# K0 Dynamic Semantics

Status: `DRAFT`

## Machine state

The Core transition relation is `Target |- State --Event?--> State'`.

```text
State = {
  control: Control,
  frames:  FrameStack,
  heap:    AllocationId -> Allocation,
  allocators: Brand -> AllocatorState,
  next_allocation_id: Nat,
  result: Running | Returned(Value) | ExplicitFailure(Value) | TargetFault(Code)
}

Allocation = {
  brand: Brand,
  type: Type,
  value: Initialized(Value) | Uninitialized,
  alive: Bool
}
```

Fresh identifiers are semantic atoms. Programs cannot observe their numeric
representation in K0, so executions differing only by a bijective renaming of
fresh identifiers are equivalent.

## Evaluation order

Compound expressions evaluate subexpressions left to right. Arguments finish
evaluation and ownership transfer in source order before the direct callee frame
is entered. There is no user code between two listed Core steps unless a direct
call step names it.

## Primitive transition table

| Operation | Preconditions | State transition | Event/failure |
|---|---|---|---|
| `copy p` | `p` initialized and `Copy(type(p))` | produce equal value; keep `p` | otherwise static rejection |
| `move p` | `p` initialized; no overlapping borrow | produce value; mark `p` uninitialized | otherwise `MOVE-*` rejection |
| `borrow shared p` | initialized; no exclusive overlap | add shared BorrowId | no runtime event |
| `borrow exclusive p` | initialized; no overlap | add exclusive BorrowId | no runtime event |
| `end_borrow b` | `b` active | remove permission | no runtime event |
| `alloc a, v` | exclusive allocator access | if capacity permits, consume `v`, create fresh allocation and owner | `alloc`; otherwise return `(AllocError,v)` |
| `dealloc a, o` | matching brand; live allocation; no live borrow | move value out, invalidate allocation and owner | `dealloc` |
| `drop o` | affine owner | owner becomes unreachable; allocation stays alive | `leak` diagnostic |

Allocation failure is an ordinary sum result. The source place is moved into the
operation in both branches; on failure the same value is returned inside `Err`
and no AllocationId is created. Deallocation cannot invoke a destructor and
cannot recursively deallocate a value contained in the object.

## Control results

`break`, `continue`, `return`, explicit failure values, and target faults are
distinct control results. K0 has no unwind relation. Returning across an active
borrow or with an invalid output initialization state is statically rejected.

## Observables

K0 observables are returned values, explicit failures, declared target faults,
allocation/deallocation events, and resource diagnostics. Internal place names,
physical addresses, fresh identifier numbers, and optimization steps are not
observable.

The executable transition vectors exercise a strict subset of this model. A full
expression/control-flow evaluator remains `OPEN` and blocks G0.
