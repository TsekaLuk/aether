# K0 Static Semantics

Status: `DRAFT`

## Judgments

The normative static model uses these judgments:

```text
Delta |- type well_formed
Delta; Gamma |- place : Type @ PlaceState
Delta; Gamma |- expression : Type => Gamma'
Delta; Gamma |- statement => Gamma'
Delta; Gamma |- body : ReturnType => ExitSet
```

`Delta` contains nominal type definitions, function signatures, allocator brands,
and target constants. `Gamma` maps each place path to:

```text
PlaceState = Uninitialized
           | Initialized(CopyClass, BorrowState)
           | PartiallyInitialized(FieldMap, BorrowState)

BorrowState = Available
            | Shared(nonzero finite set of BorrowId)
            | Exclusive(BorrowId)
```

The checking algorithm is syntax directed. It returns one output environment or
one stable rejection code; it does not search for a favorable interpretation.

## Copy and move

`Copy` is a closed structural predicate:

```text
Copy(bool)                         true
Copy(unit)                         true
Copy(fixed_or_target_integer)      true
Copy(&T)                           true
Copy(&mut T)                       false
Copy(Own<T,A>)                     false
Copy(Allocator<A>)                 false
Copy([T;N])                        Copy(T)
Copy(struct F1:T1,...,Fn:Tn)       every Copy(Ti)
Copy(enum variants...)             every payload field is Copy
```

A read of a `Copy` place leaves `Gamma` unchanged and emits an explicit Core copy.
A read of any other initialized place is a move and changes that path to
`Uninitialized`. Moving a structure field changes only that named field. Moving
an array or slice element is rejected in K0.

## Borrow transfer

For a place `p`, `overlap(p,q)` is true when:

- either path is a prefix of the other;
- both paths select the same named fields; or
- an array/slice index is not proven to be a different compile-time constant.

Borrow creation applies the following transition to every overlapping place:

| Existing state | new shared | new exclusive |
|---|---:|---:|
| Available | Shared | Exclusive |
| Shared | Shared | reject `BORROW-CONFLICT` |
| Exclusive | reject `BORROW-CONFLICT` | reject `BORROW-CONFLICT` |

An active shared borrow rejects writes and moves. An active exclusive borrow
rejects every access except through that reference. Borrow end points are the
last uses computed by the normative backward liveness analysis over the resolved
control-flow graph.

## Control-flow merge

At a join, initialization facts are the intersection of reachable predecessors.
A place is initialized after the join only when initialized with the same type on
every predecessor. Available permissions are also intersected; a borrow live on
any predecessor remains conservatively live until its normalized end point.

## Allocation typing

```text
allocator : &mut Allocator<A>
value     : T                  (moved into the operation)
------------------------------------------------------ alloc
alloc(allocator, move value) : Result<Own<T,A>, (AllocError,T)>

allocator : &mut Allocator<A>
owner     : Own<T,A>          (no active borrow of its allocation)
------------------------------------------------------ dealloc
dealloc(allocator, move owner) : T
```

Allocator brand equality is nominal equality. No conversion, subtyping, erasure,
or runtime guess can establish equality between different brands. Both result
variants consume the source place: `Ok` contains the owner, while `Err` contains
the original `T`, so allocation failure preserves the value without leaving two
owners.

## Function boundary

Public parameter, result, lifetime relation, and allocator brand are explicit.
K0 function calls are direct named calls. Recursive call graphs are allowed. The
checker does not infer or synthesize a different public signature from a body.

## Determinism obligation

For a fixed `Delta`, `Gamma`, target, and resolved syntax node, checking must
produce at most one `(Type, Gamma')` or one rejection code. A complete algorithm
and proof are `OPEN` and block G0.
