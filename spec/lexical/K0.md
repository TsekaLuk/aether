# K0 Lexical Specification

Status: `DRAFT`

## Source encoding

- Source is well-formed UTF-8.
- Identifiers are ASCII in K0: `[A-Za-z_][A-Za-z0-9_]*`.
- A lifetime label token is `'` followed immediately by an identifier. Its
  canonical spelling is the exact ASCII sequence, including the leading quote.
  Labels exist only in reference types and do not create runtime values.
- Non-ASCII scalar values are permitted only inside future text/byte literal
  forms; v0.4 defines no string literal in the stable K0 subset.
- Line endings normalize to LF before tokenization. The original byte stream is
  retained by the lossless CST but does not enter `syntax_hash`.

## Trivia

- Whitespace is space, tab, LF, or CRLF.
- A line comment begins with `//` and ends before the line terminator.
- A block comment begins with `/*` and ends at the first matching `*/`.
- Block comments do not nest. EOF before `*/` is `LEX-UNTERMINATED-COMMENT`.
- Trivia separates tokens but has no Core meaning.

## Token selection

Tokenization uses maximal munch over a closed token set. Where two tokens have
the same maximal length, the fixed token table order in this document decides.
Keywords are recognized after scanning an identifier-shaped token.

Keywords:

```text
module pub const struct enum fn requires ensures invariant init
let mut move return if else while loop break continue match
true false
```

Reserved for later layers and rejected in K0:

| First layer | Reserved spellings |
|---|---|
| K1 | `unsafe effect capability linear trait impl comptime assume` |
| K2 | `async await spawn` |

Punctuators, in decreasing maximal-munch priority:

```text
:: -> => == != <= >= && ||
{ } ( ) [ ] < > , ; : . = + - * / % ! & |
```

## Integer literals

An integer literal is decimal, binary (`0b`), octal (`0o`), or hexadecimal
(`0x`). Underscores may occur only between digits. A literal denotes an exact
mathematical integer until a unique expected integer type is established. It is
rejected if no unique type exists or if its value is not representable.

No sign is part of an integer token; unary `-` is parsed separately.

## Layer boundary

A reserved word always tokenizes as `RESERVED`, never as `IDENT`. Encountering
one anywhere in a K0 source file rejects the file with
`LAYER-FEATURE-DISABLED` before parsing. The diagnostic records the token text,
byte span, requested layer `K0`, and the first layer in which the spelling may be
defined. Parser recovery cannot reinterpret or discard a reserved token in an
otherwise accepted source file.
